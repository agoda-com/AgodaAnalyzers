# Analyzer scope

False positives are the most common reason a shipped rule gets fixed (AA #219, #220, #221, #235, #242; SFA #19). Each one was a context the rule wasn't meant for. Before writing `ReportDiagnostic`, write down **the narrowest context where this rule should fire**, then gate on exactly that.

## 1. Test-only rules use real test detection

A class is test code if **any** of these hold (OR, not AND):

1. it or a base class has `[TestFixture]` / `[TestClass]`
2. **any method** in it has `[Test]`, `[TestCase]`, `[TestCaseSource]`, `[Fact]`, `[Theory]` or `[TestMethod]`
3. a namespace segment *ends with* `Test` or `Tests` (`MyApp.Tests`, `MyApp.IntegrationTests`)

```csharp
// Don't: prefix match. "TestimonialService", "TestData.Seed" are production code.
if (ns.StartsWith("Test")) ...
// Don't: class attribute only. xUnit has no class attribute; NUnit's is optional.
if (HasAttribute(type, "TestFixture")) ...
```

The namespace check backs up the attribute checks; it never replaces them. Resolve attributes by symbol (see `roslyn-symbol-based-detection`). List the supported frameworks in the rule doc. Sample helper in [references/test-context-detection.md](references/test-context-detection.md).

Evidence: AA #226 (AG0051 fired on production seed data), #228 (`StartsWith("Test")`, no xUnit, no method-level check).

Roslyn can't see MSBuild properties like `IsTestProject` unless the package's `.props` marks them `CompilerVisibleProperty`. Don't rely on them without shipping that.

## 2. Blacklists match the call site, not the identifier

```csharp
// Don't: flags every use of the enum member: assignments, comparisons, switch labels.
new BlacklistedInvocationRule("Microsoft.Playwright.LoadState", "NetworkIdle")

// Do: flag the member only as the argument of the API that makes it harmful.
if (invocation.TargetMethod.Name == "WaitForLoadStateAsync"
    && IsPlaywrightType(invocation.TargetMethod.ContainingType)
    && invocation.Arguments.FirstOrDefault()?.Value is IFieldReferenceOperation { Field.Name: "NetworkIdle" })
    Report(...);
```

AG0040 still uses the global form (AA #226 review). Don't copy it into a new rule.

## 3. Gate on the API, not on the file

```csharp
// Don't: AG0045 (#235) skips files without `using Microsoft.Playwright`.
// Misses global usings and fully-qualified calls, and still fires on any string in a file that has the using.
// Do: only inspect string arguments that flow into an IPage/ILocator locator method (symbol check).
```

## 4. Generated code, on purpose

- Call `ConfigureGeneratedCodeAnalysis(GeneratedCodeAnalysisFlags.None)` unless the rule is *about* generated code.
- Think about hand-written code that looks generated, and generated code that doesn't carry an `<auto-generated>` header (GraphQL client models in a normal folder, AA #213).

## 5. Time- and environment-dependent rules

A rule that reads the clock gives different answers on different days. Suppress what's already safe and document it:

- AG0051 skips dates in a month that has fully elapsed, and sentinel years `>= 2999` (AA #242).
- Say in the rule doc that results depend on the analysis date.
- Read the clock per compilation (in `RegisterCompilationStartAction`), not in a `static readonly` field. An IDE process can live for days, so AG0051's `static readonly DateTime AnalysisDate = DateTime.UtcNow.Date` goes stale after midnight.
- Tests must not depend on today's date: pick dates far in the past/future, or inject the clock.

## 6. Name three non-target sites before merging

For each, add a negative test. Candidates:

- log message strings, regex literals, URLs, file paths, comments (AG0045 #219–#221: `//` in URLs and log messages looked like XPath)
- a user type or method with the same simple name (SFA #19)
- the same API in production code when the rule is test-only
- nested blocks, local functions, lambdas (AA #230: wait in an outer block, screenshot in a nested `if`)
- helper wrappers (`await WaitUntilReady(page); await page.ScreenshotAsync();`). Decide: support, or document as a known false positive.

## Fixing a false positive

Another `if` rarely fixes it. Find the dimension the rule ignored (context, call site, shape, generated code, time), gate on it, and add a regression test named after the issue.

## Checklist

- [ ] Intended context written in the PR description and the rule doc's scope section.
- [ ] Test-only rules: class attribute OR any test method attribute OR namespace segment suffix. Frameworks listed.
- [ ] Blacklisted members only reported as arguments of the harmful API.
- [ ] Generated-code handling is explicit.
- [ ] Time-dependent behaviour suppresses already-safe values and is documented.
- [ ] At least three non-target sites, each with a negative test.
