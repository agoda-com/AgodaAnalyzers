# Use PascalCase for Named Placeholders

ID: S6678 (owned by [SonarAnalyzer.CSharp](https://rules.sonarsource.com/csharp/RSPEC-6678/))

Type: Code Smell / Consistency

> [!WARNING]
> **Applying this fix renames the structured properties your logs emit.** `{userId}` becomes `{UserId}`, so
> every dashboard, saved search, alert and log-based metric keyed on `userId` stops matching the moment the
> change is deployed. Agree the rename with whoever owns those dashboards *before* you run it, and expect to
> update queries in the same change. This is not a mechanical cleanup you can wave through in review.

## Summary

Serilog message template placeholders become the names of the structured properties attached to the log event.
Agoda's convention - and Sonar's S6678 - is that those names are PascalCase. This repo ships a **code fix only**
for S6678: it uppercases the first letter of each named placeholder inside an existing message template.

## This ships as a fixer, with no new AG rule

There is deliberately no `AG00xx` analyzer for this. Nothing new shows up as a build warning, nothing fails CI,
and nobody "fixes" it in passing while working on something else. Because of the property-rename risk above,
the change has to be a deliberate, per-repo decision.

Two consequences:

1. **Nothing is reported unless you reference `SonarAnalyzer.CSharp`.** The fixer registers itself against the
   diagnostic ID `S6678`, which that package owns. Roslyn matches code fix providers to diagnostics by ID
   regardless of which assembly reported them, so the fix lights up wherever Sonar is referenced and is simply
   inert everywhere else.
2. **You run it on purpose**, from the repo root:

   ```
   dotnet format analyzers --diagnostics S6678
   ```

   Fix All is supported (`WellKnownFixAllProviders.BatchFixer`), so the whole solution is rewritten in one pass.
   In an IDE the fix is also offered per occurrence, and via *Fix all occurrences in Document / Project / Solution*.

## What the fix does

It is a purely textual edit inside the existing string literal - only the first letter of a placeholder name
changes, so the rest of the template, the other arguments of the logging call, and all surrounding trivia are
preserved exactly.

### Don't ❌

```csharp
_logger.LogInformation("{service}.{method} called for {userId}", service, method, userId);
_logger.LogInformation("Loaded {@propertyId}", propertyId);
_logger.LogWarning("Price {price,-10:F2} out of range", price);
```

### Do ✅

```csharp
_logger.LogInformation("{Service}.{Method} called for {UserId}", service, method, userId);
_logger.LogInformation("Loaded {@PropertyId}", propertyId);
_logger.LogWarning("Price {Price,-10:F2} out of range", price);
```

### Preserved

| Shape | Before | After |
| --- | --- | --- |
| Destructuring prefix | `{@propertyId}` | `{@PropertyId}` |
| Stringification prefix | `{$x}` | `{$X}` |
| Alignment clause | `{userId,10}` | `{UserId,10}` |
| Format clause | `{price:F2}` | `{Price:F2}` |
| Both | `{price,-10:F2}` | `{Price,-10:F2}` |
| Verbatim / raw literals | `@"... {userId}"` | `@"... {UserId}"` |

### Left alone

| Shape | Why |
| --- | --- |
| `{0}`, `{1,5:F2}` | Positional placeholders are argument indexes, not property names. |
| `{{name}}`, `{{0}}` | `{{` and `}}` are escaped literal braces, not placeholders. |
| `{_state}` | Names starting with `_` are left as written. |
| `{UserId}` | Already PascalCase - no edit. |
| Anything the fixer cannot resolve to a single string literal | No fix is offered, rather than a guess. |
